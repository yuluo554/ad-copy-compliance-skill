## 3. 合成数据纪律

本项目全部评测样例为**合成文案**，必须遵守：

1. **假品牌名/假商品白名单**：基准与演示一律使用明显虚构的品牌名与商品名（如"测试品牌A""示例商品B"），**统一登记白名单**；**禁止引用任何真实品牌的违规案例或真实商品文案入库为基准样例**。
2. **不植入真实内容**：禁止从任何真实推广文案、真实违规案例、平台真实处罚公告中复制内容进入样例集。
3. **植入真值显式登记**：每个合成样例的元数据必须登记"**应命中哪些词**（`expect`）、**应判为何种分层结论**（`expect_verdict`：confirmed / exempt / uncertain）"，使基准能断言**命中集合（词 + 位置）精确匹配**，而非仅布尔式准确率。
4. **每形态都要有采样件**：规则的每个类别/风险形态都须有 ≥1 份样例提供真值，并在 manifest 登记采样数（分子）与采样清单；**有词条却零采样件 → 基准判未达标**。
5. **覆盖易错形态**：样例集须显式覆盖三类边界——①**语境豁免**（如引述他人、法定用语、客观事实陈述）不冤枉用户；②**同词异类**（同一词在不同品类下风险等级不同）；③**未命中**（合规文案零命中，验证不误报）。
6. **覆盖度口径**：基准覆盖度按**规则域与异常类型**列最低覆盖项（如"绝对化用语/医疗/保健食品/行业各至少 X 例"），口径写进 manifest 或 `plan/00` 台账；**不写会随实现漂移的硬数字**，确需数字时写"以末态回填"。

## 4. 数值口径纪律

- **一处定义、多处引用**：规则/词条只在 `references/`（`statutes/`、`platforms/`、`wordlists/`）中定义一次，扫描器（`scripts/check.py`）、判定层、基准、文档全部引用同一处；**禁止在文档或注释里手写第二份口径**。
- **不预设硬数字**：词条数与样例数**不写进题面**，以"挂原文核对后的词条"与"构造真值后的样例"为准；基准门槛是**数据不是代码**，写进 manifest。
- **锚点强制**：`references/wordlists/` 每条须携带：来源（官方/公开整理）+ 类别 + 风险等级 + **依据条款锚点**（法条文件名 + 条款号）；**未挂原文核对的词条不得被扫描器加载生效**。
- **平台规则定性**：`references/platforms/` 每条须注：平台 + 摘录日期 + 原页 URL + 摘录人；**人工摘录件不得声称"官方实时口径"**。
- **法条冻结**：`references/statutes/` 为**冻结字节件**，登记 sha256；不得 EOL 归一化（见 `.gitattributes`），否则克隆后 sha256 失配。
- **词表性质声明**：公开整理词表须显式标注"**非官方整理，法条原文为准**"；不得冒充官方口径。

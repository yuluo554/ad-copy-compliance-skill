## 1. 规则化方法：为什么"词表 + 锚点"而不是"让模型看着办"

本项目的核心判断是：**合规检查的第一层必须是确定性的**。纯 prompt 方案有三个不可接受：
命中不可复现（同一句文案两次问结果不同）、位置不可定位（无法逐字标红）、规则不可审计
（没人说得清模型到底按什么标准判定）。

因此本工具把"什么词受限于哪条法条"做成**冻结的规则数据**：

- **词面**来自公开整理词表快照（逐条标注"非官方整理，法条原文为准"）；
- **锚点**把每个词条挂到冻结法条的具名条款（如《广告法》第九条），`literal` 类词条
  要求词面**逐字出现**于条款正文——"挂没挂原文"不是声明，是断言；
- **未挂原文核对不得落库**：核对未完成的候选词留在工作台账（`data/wordlist-candidates.md`），
  不进规则包、不被引擎加载；
- **门控加载**：引擎只加载 `status=="verified"` 且锚点可解析的词条；被拒条目在 stderr
  显式列出（未启用清单＋原因）——词表坏了是"可见的降级"，不是静默的空扫。

规则与代码严格分离：词表/法条只定义在 `references/`（一处定义），脚本与测试源码不得内嵌
任何 ≥3 字词表词面（门禁测试锁定，M2/D-10），规则内容只能运行时加载。

## 2. 扫描-判定分工：确定性归机器，语境归协议

架构上把"命中"与"违规认定"拆开：

- **扫描层（`scripts/check.py`）**：零 LLM、零网络、零第三方依赖。输入文案纯文本，
  输出命中集合 JSON（7 字段固定契约：`word/category/risk/line/col/context/suggestion`）。
  同一输入 → 同一命中集合与同一位置（无随机、无时间、无环境依赖），命中位置可逐字定位。
- **判定层（宿主 Agent 会话内）**：按 `references/judgment-protocol.md` 对每条命中做
  **注释副本**——只追加 `verdict`（`confirmed`/`exempt`/`uncertain` 三态）、
  `verdict_reason`、`verdict_anchor` 三字段，**不得新增/删除/移动任何命中**（K10，
  结构测试锁定）。三态下限：`exempt` 必须给理由＋锚点（不承认默认豁免）；
  `uncertain` 必须说明"为何无法判定"（非垃圾桶）。
- **降级路径**：判定关闭或失败 → 全部命中标 `uncertain`＋输出 meta 显式声明
  "仅扫描结果，未经语境判定"——工具的可用性不依赖 LLM 在场。

这个分工让两件事同时成立：扫描结果可以进 CI（机器可读、退出码三语义、逐字节可复现），
而合规判断的语境复杂性（引述他人原话、法定专名、非宣称语境）交由有依据的判定协议处理，
且判定产物明确标注"可复现性弱于扫描层"。

## 3. 三层规则包设计

```
references/
├── statutes/    法条原文冻结（广告法 / 互联网广告管理办法 / 医疗广告管理办法，raw+txt 双件）
├── platforms/   平台规则人工摘录（视频号已冻结；淘宝/抖音/小红书官方页 JS 渲染不可得，如实标 ⬜）
├── wordlists/   分类词表 4 类 133 条 verified（绝对化用语 50 / 行业违禁 47 / 保健食品 22 / 医疗 14）
└── MANIFEST.json  规则包清单（文件 sha256＋计数；rulepack_version 由内容派生，禁手写）
```

设计要点：

- **冻结纪律**：法条 txt、词表 JSON、样例 cases/manifest 均为冻结件（`.gitattributes -text`，
  禁手改）；任何变更走生成器重生成＋`--check` **位级一致**守门——"规则包更新了什么"永远可以
  diff、可以复现。
- **条款抽取语义**：条号只认行首定义位（正文中交叉引用不参与切分），抽取结果回读原文逐字校验。
- **版本化**：工具版本唯一处（`check.py __version__`）；规则包版本由文件内容 sha256 派生。
  文档/报告引用版本一律取派生值，不手写常量。

## 4. 基准设计：真值不手写，观测不落库

`data/samples/cases.json`（148 条，冻结）＋ `tools/bench.py`（一条命令复现评测）：

- **样例构成**：逐词全量 133（每生效词条 1 条单词命中）＋多词 2＋负例 3＋位置边界 6
  （BOM/CRLF/CR＋行首/行尾/跨行）＋判定类 6（`expect_verdict`：confirmed 2 /
  exempt 2 / uncertain 2，仅供有 LLM 时评估，**不进 bench 断言**）。
- **真值纪律（D-12）**：`expect_hits` 不手写——生成器内置**独立朴素 oracle**（逐词 find，
  与 DFA 引擎不共用代码）运行时实算；生成期守卫断言 oracle 与引擎对全部样例及全词面拼接
  语料逐位一致。真值只存"输入与期望"，禁 `observed` 类观测字段（加载侧与测试双侧拒绝）。
- **比对语义**：命中集合（词＋类别＋行＋列）**双向精确比对**（不漏不增）；验收门槛
  `exact_match_required=1.0` 随 `data/samples/manifest.json` 下发（**数据非代码**），
  manifest 缺失即配置错误 exit 2，不回落代码默认值。
- **可证伪性**：三形态探活测试全部打到 bench 进程入口——①篡改一条真值→必红；
  ②注入空词表→必红；③坏锚点注入→必红。基准不是"跑过就绿"的摆设，注入必被逮住。
- **覆盖口径**：`manifest.sampling` 总数/采样数双数登记（133/133 词、148 cases）＋采样清单＋
  "抽样覆盖非穷举"显式声明——不虚报覆盖率。

## 6. 局限与免责

**方法局限（如实陈述）**：

- **词表是抽样的，不是穷举的**：133 条覆盖《广告法》第九条绝对化用语与四类违禁表述的
  高频词面；未入词表的变体表述（如组合式、谐音式）扫不到——扫描漏了的不由判定层补，
  那是词表 backlog。
- **词面来源非官方**：公开整理快照＋法条锚点核对；法条原文为准，锚点核对不等于执法口径。
- **平台层仅 1/4 冻结**：淘宝/抖音/小红书官方社区规范页纯 JS 渲染不可自动获取，
  如实标 ⬜（已记录查询渠道）；平台结论不进首期机器输出。
- **语境判定在会话内、可复现性弱于扫描层**：同一段文案的 verdict 可能随会话证据变化；
  降级路径保证 LLM 缺席时工具仍可用（全 uncertain＋显式声明）。

**免责（统一措辞，K12）**：

- 本工具为辅助自查提示，**不构成法律意见、不构成合规保证、不构成行政认定**；
  正式结论以主管部门口径与专业律师意见为准。
- **零命中 = "未检出词表命中"，不等于合规**。
- 纯本地处理、零上传；不自动发布、不自动改写上线，只给建议供人决策。
- 基准与演示一律使用假品牌白名单合成文案，不引用真实品牌违规案例。

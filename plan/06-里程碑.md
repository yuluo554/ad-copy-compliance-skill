## 2. 诚实口径（CI 状态措辞纪律）

- **未推送 = 未跑 CI**。M0–M5 的 CI 类 DoD 一律写"**本地等价校验（未接远端，CI 待首推验证）**"，禁止写"CI 绿"。
- **本地等价校验清单**（可指认的替代证据，逐项跑）：① 双解释器全量 pytest（`py -3.8` / `py -3.12`）；② 生成器 `--check` 位级一致（M1/M4 起）；③ 基准 `bench`（M4 起）；④ 门禁测试（import 白名单/契约/词面）；⑤ 冻结态验收（对 Skill 形态即"干净副本 + README 逐条"，M6）。
- **不可本机实跑的通路**（CI 环境差异：矩阵系统/编码/浅克隆等）显式标注"**待首推验证**"。
- M6 首推后：据实补记真实结论与 run id；首跑若红，失败与修复提交**如实配对留档**（不遮掩、不回填美化）。

## 3. 收尾与记录纪律

- **每棒 commit**：里程碑之间不留"只存在于工作树"的成果（历史=事实；发布期任何历史操作只认已提交内容）。
- **计数同步**：测试数/词条数/样例数等跨文档数字当轮实测；会随动作增长的量写"取值方式＋快照点"。
- **既定口径（K 清单）**：见 `plan/04` §0；改任何 K 项 = 同步改引擎/测试/文档/基准，并登记 `plan/00` 决策记录。
- **决策表**：`plan/07` §4 —— 未获拍板前按推荐默认执行；获拍板后回写。
- **品牌隔离**：计划文档提及系列/姊妹项目一律用"方向级描述"，不落具体领域名词。
- **缓议项**：临期项必须在 M6 收尾前清零（含显式"跳过"决策）。

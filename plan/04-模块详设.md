## 0. 全局口径速查（K 清单）

| K | 口径 | 一处定义 |
|---|---|---|
| K1 | **输出契约（扫描层）**：JSON 数组，元素字段固定且仅有 `word, category, risk, line, col, context, suggestion`；`verdict` 类字段只出现在判定层产物 | `scripts/check.py` `HIT_FIELDS`＋SKILL.md 契约块（一致性测试锁定） |
| K2 | **匹配语义**：左→右扫描；每个位置取最长匹配（多词表条目按词长降序）；**非重叠**（命中段消费后从段尾继续）；同词多类别各记一条；输出排序 = 扫描序（line, col, category, word） | `scripts/check.py` `scan_text()` |
| K3 | **位置语义**：行号/列号均 **1 起**；列按 Unicode 码点计；CRLF/CR 归一为 LF、UTF-8 BOM 剥离后计数 | `scripts/check.py` 输入规范化 |
| K4 | **退出码**：`0` = 扫描完成且零命中；`1` = 扫描完成且有命中；`2` = 用法或输入错误（文件不存在/非 UTF-8/参数错误/词表目录缺失）；`--exit-zero` 令命中时也退 0 | `scripts/check.py` `main()`，锁进测试 |
| K5 | **词表门控**：仅 `status=="verified"` 且锚点可解析的条目加载；被拒条目经 stderr 显式列出（未启用清单＋原因）；`basis=="literal"` 时词面必须逐字出现于冻结条款正文 | `scripts/check.py` `_load_entries()` |
| K6 | **规则单一定义**：词表/法条/平台规则只在 `references/` 定义；`scripts/` 源码（含注释/文档串）不得内嵌词表词面（门禁测试，token 由规则包运行时实算） | M2/M5 门禁（归属 `tests/test_repo_gates.py`） |
| K7 | **零依赖零外联**：`scripts/` 仅 stdlib；import 白名单断言，含网络模块即红 | `tests/test_repo_gates.py` |
| K8 | **合成数据**：假品牌白名单；不引真实品牌案例；真值只存"输入与期望"（禁 `observed` 类字段） | `data/README.md` §3＋`plan/05` §5 |
| K9 | **基准**：命中集合**精确匹配**（词＋位置，双向：不漏不增）；覆盖度"总数/采样数"双登记＋采样清单；验收门槛随 manifest 下发（数据非代码）；探活必红 | `data/samples/manifest.json`＋`tools/bench.py` |
| K10 | **判定层**：只改 `verdict/verdict_reason/verdict_anchor`，不动 `word/line/col`；不可用→全 `uncertain`＋降级声明 | `references/judgment-protocol.md` |
| K11 | **平台层**：摘录件注 平台/摘录日期/原页 URL/摘录人/范围；不得声称"官方实时口径" | `references/platforms/` 头部元数据块 |
| K12 | **免责与措辞**：输出与文档强制携带免责声明；**零命中 = "未检出词表命中" ≠ 合规**（统一措辞） | SKILL.md / README / 报告模板 |
| K13 | **编码**：入口 `_ensure_utf8_stdio()`＋CI `PYTHONUTF8=1`＋子进程显式 `encoding`（口径保留） | `scripts/check.py` 入口 |
| K14 | **版本**：工具版本 = `check.py __version__`（唯一处）；规则包版本由 `references/MANIFEST.json` 内容派生（禁手写） | `references/MANIFEST.json` |
| K15 | **冻结产物**：法条/词表/样例为冻结构（禁手改；变更走工具重生成，配 `--check` 位级一致守门）；发布 zip（M6）用 `ZIP_STORED`＋固定时间戳＋条目排序 | 各生成器＋`tools/` |

## 1. 模块① SKILL.md 主入口（FR-1）

**职责**：skill 的触发描述、调用方式、输出契约、工作流、免责声明。
**结构**：

## 2. 模块② 三层规则包（FR-5/6/7）

### 2.1 第一层 `references/statutes/` — 法条冻结

- **文件**：`advertising-law.txt`（《广告法》全文；§9/§16/§18/§28 为锚点目标）、`internet-ad-measures.txt`（《互联网广告管理办法》全文 32 条）、`medical-ad-measures.txt`（《医疗广告管理办法》；§6/§7 为锚点目标）；`raw/` 存原始 HTML 快照；`README.md` 为来源表（逐部：来源 URL／基准日／查证状态／字节数／raw 与 txt 双 sha256／抽取工具版本）。
- **纪律**：冻结字节件（`.gitattributes` `-text`）；禁手改；变更走 `tools/build_statutes.py` 重生成＋`--check` 位级一致。
- **条款抽取（供锚点解析）**：条号**只认行首定义位**（`^第X条（之一）`），正文中交叉引用不参与切分；抽取结果必须**回读原文逐字校验**（`literal` 词面断言其出现在该条款块内）。
- ⚠️ 执法指南（一）（二）存在但**不涉及绝对化用语认定口径——勿误标为认定依据**（沿 `data/README.md` §1 #4）。

### 2.2 第二层 `references/platforms/` — 平台规则人工摘录冻结

- **文件**：`taobao.md` / `douyin.md` / `xiaohongshu.md` / `shipinhao.md`；每份头部元数据块：平台 / 摘录日期 / 原页 URL / 摘录人 / 摘录范围 / **性质声明（"人工摘录快照，非官方实时口径"）**。
- **获取策略**：官方社区规范页纯 JS 渲染不可自动抓——M1 尝试可达通道（帮助中心、开放平台文档、静态子页）；仍不可得则如实标 ⬜＋已查渠道记录（降级继续，不阻塞）。
- **首期定位**：审计素材＋判定层可引锚点；机器化多平台输出为扩展（FR-E2）。

### 2.3 第三层 `references/wordlists/` — 分类词表

- **文件与类别**（文件名→类别，逐条 `category` 必须与文件声明一致，校验器强制）：
  `absolute-terms.json`→`绝对化用语`；`medical.json`→`医疗违禁`；`health-food.json`→`保健食品违禁`；`industry.json`→`行业违禁`。
- **条目 schema**：

```json
{
  "word": "国家级",
  "category": "绝对化用语",
  "risk": "high",
  "anchor": {"doc": "advertising-law", "clause": "第九条", "basis": "literal"},
  "source": {"type": "non_official", "ref": "公开整理词表（来源快照）", "note": "非官方整理，法条原文为准"},
  "status": "verified",
  "suggestion": "删除该表述，或改为可核实的客观事实描述"
}
```

- **枚举**：`risk ∈ {high, medium, low}`（展示层映射 高/中/低）；`basis ∈ {literal, variant}`（`variant` 必须带 `note` 说明为何属该条款开放的"等用语"语义类属；`literal` 必须词面逐字出现于条款正文）；`status ∈ {verified, pending}`（引擎只加载 `verified`）。
- **落库纪律（"未挂原文核对不得落库"的操作化口径，D-3）**：规则包文件**只收挂锚点条目的 `verified` 条目**；核对未完成的候选词留在 `data/wordlist-candidates.md` 工作台账（采/拒记录、理由），不进规则包、不被引擎加载。
- **排序**：按 `word` 码点序（校验器强制），保证冻结产物可 diff、可位级复现。
- **来源定性**：公开整理（`es3344520/advertising-limit-words` Dete.txt 约 300 词快照值；`dx2020z/ad-redline-guardian` banned-words.md 分类参照），**非官方**，逐条标注；来源仓库许可在台账登记。
- **校验器 `tools/validate_rulepack.py`**：schema/枚举/文件-类别映射/同文件同词唯一（跨文件同词=同词异类，允许）/锚点解析/literal 词面存在/suggestion 非空/排序；`--check` 退出码 0/1/2；`--write-manifest` 更新 `references/MANIFEST.json`（文件 sha256＋计数＋版本派生）。

### 2.4 版本化（`references/MANIFEST.json`）

- 字段：`rulepack_version`（由文件列表 sha256 派生，工具计算）、`base_date`、`files[{path, sha256, bytes}]`、`counts{words_verified, words_by_category, cases, ...}`。
- **版本号从数据派生**：报告/CLI 双出口取同一处派生值，禁手写常量。

## 3. 模块③ 确定性扫描器 `scripts/check.py`（FR-3/4）

### 3.1 CLI

```
python scripts/check.py [输入文件|"-"] [--wordlists-dir DIR] [--statutes-dir DIR]
                        [--context N] [--format json|text] [--exit-zero]
                        [--version] [--selftest]
```

- 输入：UTF-8 文本文件，或 stdin（省略参数或 `-`）；空输入合法（零命中）。
- `--format json`（默认，机器契约）；`--format text`（人读展示，**非**机器契约）。
- `--selftest`：内置合成数据自检（进 CI 冒烟）；成功打印 `SELFTEST_OK`。

### 3.2 输出契约（K1）

stdout = JSON 数组（`ensure_ascii=False`，缩进 2）；元素字段固定 7 个、序固定：

| 字段 | 类型 | 语义 |
|---|---|---|
| `word` | str | 命中的词表项（原样） |
| `category` | str | `绝对化用语`/`医疗违禁`/`保健食品违禁`/`行业违禁` |
| `risk` | str | `high`/`medium`/`low` |
| `line` | int | 行号（1 起，K3） |
| `col` | int | 列号（1 起，按码点，K3） |
| `context` | str | 命中处上下文窗口（默认左右各 10 字符、按行截断；**纯子串**，不添加省略号——可逐字回查） |
| `suggestion` | str | 词表内置确定性替换建议（K1：不做自由生成） |

诊断信息（未启用条目、生效条数、词表缺失提示）走 **stderr**，不进 stdout（保持机器契约纯净）。

### 3.3 匹配语义（K2）与实现路线

- **M0 骨架**：按词首字符索引＋`startswith` 逐位最长优先（语义已成，性能 O(行×候选)）。
- **M2 目标**：升级为 trie/DFA（多模式一趟扫描；状态机走位取"当前位最长的已注册词"）——**语义不变**，只提性能与"一趟扫描"表述对齐（题面 §2 模块③）。
- 同词多类别：同一命中段、同词、不同 `category` 各记一条。
- **默认建议（M2）**：`--context` 校验 `>=0`；`--format text` 输出 `行:列  词  [类别/风险]  上下文`。

### 3.4 门控加载与未启用清单（K5）

- 加载顺序：读 `references/wordlists/*.json`（排序后逐个）→ 逐条校验 `status`→锚点（文件存在→条款可抽取→literal 词面包含）→ 通过者生效。
- **被拒条目逐条打印 stderr**：`未启用条目：<文件>/<词>/<原因>`（原因码：`status 非 verified`、`锚点文件缺失`、`条款解析不到`、`literal 词面未见于条款`、`缺字段`、`文件不可解析`）。
- 词表目录不存在 → **exit 2**（"路径不存在要大声说"，不静默空扫）；目录存在但零生效条目 → stderr 明示＋正常零命中（M0 常态；M2 可增 `--strict` 选项评估）。

### 3.5 失败路径（全部锁测试）

| 情形 | 行为 |
|---|---|
| 文件不存在 | exit 2，stderr 说明 |
| 非 UTF-8 字节 | exit 2，stderr 说明 |
| 未知参数/无效参数值 | exit 2（argparse 语义） |
| 词表目录缺失 | exit 2 |
| 词表文件坏 JSON | 该文件记入未启用清单（原因"文件不可解析"），其余继续 |
| 空输入 | exit 0，输出 `[]` |

### 3.6 确定性验收

- 同一输入两次运行 stdout **逐字节一致**（测试锁定）。
- 每个命中 `(word,line,col)` 可在原文**逐字定位**（测试用切片断言）。
- 排序稳定（K2）；无时间戳、无随机、无环境依赖。

## 4. 模块④ LLM 分层判定协议（FR-8，M3 交付）

**定位**：判定层的执行者是宿主 Agent（Claude Code / Codex 会话内），按 `references/judgment-protocol.md` 操作；**本项目自身无外发通路**。

### 4.1 输入输出

- 输入：扫描层输出（命中集合）＋原始文案（同会话内）。
- 输出：对**每条命中**的注释副本，**追加**字段：`verdict ∈ {confirmed, exempt, uncertain}`、`verdict_reason`（判定理由）、`verdict_anchor`（依据条款/平台摘录锚点）。**不得**新增/删除/移动任何命中（K10）。
- 附 `meta`：`{"judgment": "on|off|failed", "note": "..."}`。降级时（off/failed）所有命中标 `uncertain`＋note 声明"仅扫描结果，未经语境判定"。

### 4.2 三态语义（首版框架，M3 结合锚点细化）

| 状态 | 含义 | 典型情形（示例，M3 细化并配样例） |
|---|---|---|
| `confirmed` | 语境中属明确受限表述 | 直接向消费者宣称（无豁免特征）的 §9 类用语等 |
| `exempt` | 语境豁免（有依据，必须给理由＋锚点） | 引述法律条文/他人原话；法定专名与官方认定的规范表述；明确的非宣称语境 |
| `uncertain` | 需人工复核（**非垃圾桶**：必须说明"为何无法判定"） | 证据不足（如"销量第一"是否有可核实依据）、语境复杂、LLM 不可用 |

### 4.3 边界纪律

- 扫描层**零 LLM**（K7）；判定只对已命中候选工作（扫描漏了的不由判定补——那是词表的 backlog）；
- 判定不得改变位置字段；判定产物明确标注"判定层产物，可复跑性弱于扫描层"；
- **不输出合规结论**（K12）；输出必含免责；
- 判定协议必须覆盖"降级路径"并配测试（关闭→纯扫描；失败→全 `uncertain`＋声明）。

## 5. 模块⑤ 真值基准（FR-9，M4 交付）

### 5.1 样例与真值（`data/samples/`）

- 文件：`cases.json`（冻结构，生成器产出）＋`manifest.json`（计数/双数/采样清单/验收门槛）。
- 样例 schema：

```json
{
  "id": "pos-0001",
  "kind": "positive-per-word | multi-word | negative | position-edge | same-word-multi-category | exempt",
  "text": "……合成文案（假品牌名）……",
  "expect_hits": [{"word": "最佳", "category": "绝对化用语", "line": 1, "col": 5}],
  "expect_verdict": "confirmed | exempt | uncertain | null",
  "note": "植入说明"
}
```

- **真值纪律**：只存"输入与期望"（K8）；`expect_hits` 为**精确集合**（比对语义=集合相等，双向）。

### 5.2 生成器 `tools/gen_cases.py`

- **确定性**：枚举式构造（禁 stdlib `random`、禁 set 迭代序、禁时钟）；无时间戳；`--check` 重生成与入库件位级一致。
- **构造方式**：固定良性模板＋按词表枚举植入（每生效词条 ≥1 条"单词命中"样例，词条总数=该形态采样数）；另接手工设计的语义样例（多词/负例/边界/判定）。
- **覆盖口径（写进 manifest）**：①逐词全量（自动）；②每类别 ≥1 多词 / ≥1 负例；③位置边界（行首/行尾/跨行/CRLF/BOM）；④同词异类（存在时）；⑤判定类样例（标注 `expect_verdict`，供有 LLM 时评估；离线基准只断言扫描层）。覆盖声明按"总数/采样数"双数登记＋采样清单；如非穷举必须显式声明"抽样覆盖非穷举"。

### 5.3 基准运行器 `tools/bench.py`

- 一条命令：加载 `cases.json` → **运行时实算**（真喂 `check.py` 的扫描函数）→ 与 `expect_hits` 集合比对 → 人读摘要＋机读 JSON。
- 判定：全部样例精确匹配 → exit 0；任一不匹配或门控拦截 → exit 1；用法/配置错误 → exit 2。
- 验收门槛（`manifest.acceptance`，数据非代码）：`exact_match_required = 1.0`；缺失即配置错误 exit 2，不回落到代码默认值。
- **探活（每套件配可证伪测试）**：至少三形态——①篡改一条真值→必红；②禁用匹配（注入空词表）→必红；③坏锚点注入→该词不生效→相关样例必红。探活必须打到**端到端入口**（断言 `bench` 进程/主函数返回非 0），不断言"调了某函数"。

### 5.4 指标口径

- 主指标：**命中集合精确匹配率**（合成集；末态实测写入 README）；辅指标：逐类别 P/R（参考值，不作为唯一门）。
- **不预设硬数字**：样例数量、指标值以末态实测回填；门槛值随 manifest 下发。

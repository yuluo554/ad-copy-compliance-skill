## 2. 法条冻结（M1 执行卡）

**目标文件**（以 `data/README.md` §1 为准）：

| doc 标识 | 文本 | 锚点目标 |
|---|---|---|
| `advertising-law` | 《中华人民共和国广告法》全文 | §9 绝对化用语 / §16 医疗 / §18 保健食品 / §28 虚假广告 |
| `internet-ad-measures` | 《互联网广告管理办法》全文 32 条 | 与广告发布/用语相关的禁止性条款 |
| `medical-ad-measures` | 《医疗广告管理办法》 | §6 / §7 禁止性规定 |

**流程（脚本化，`tools/build_statutes.py`）**：

1. **抓取**：curl 落盘原始 HTML（带 UA、超时与重试；网络与代理坑见 §7）→ `references/statutes/raw/<doc>.html`。
2. **抽取**：HTML → 正文文本快照 `references/statutes/<doc>.txt`（确定性转换；字符集检测与处理方式记入工具日志与 README 来源表）。
3. **逐字断言**（核对器，抽取值均需回读原文）：
   - 关键串逐字出现：如广告法快照必须含 `第九条`、`国家级`、`最高级`、`最佳`；
   - 条款抽取：`^第X条（之一）` 行首定义位可解析（**交叉引用不参与切分**）；目标条款逐条可抽取；
   - 全文条数记录（如互联网广告办法 32 条）。
4. **登记**：`references/statutes/README.md` 逐部登记 来源 URL / 基准日 / 查证状态 / 字节数 / **raw 与 txt 双 sha256** / 抽取工具版本。
5. **守门**：`tools/build_statutes.py --check`：从本地 raw 重生成 txt，**位级一致**（不允许网络）。

**纪律**：

- 冻结字节件——`.gitattributes` 已配 `references/statutes/*.txt -text`（禁 EOL 归一化，否则克隆后 sha256 失配）；`raw/` 一并纳入 `-text` 范围（M1 落地时补规则）。
- 禁手改；变更 = 重取＋重生成＋更新 sha256＋记录勘误。
- ⚠️ 来源坑（沿 `data/README.md` §2.1）：gov.cn 旧路径大面积 404（一律以 samr.gov.cn 为准）；`content_5647633.htm` 是《著作权法》勿引用；`flk.npc.gov.cn` JS 渲染；`nmpa.gov.cn` 412。
- 法条文本为官方文件（不适用著作权保护），随仓冻结可复核。

## 3. 分类词表（M1 执行卡）

**词源与获取**：

- 主来源快照：`es3344520/advertising-limit-words` 的 `Dete.txt`（约 300 词，快照值）；
- 分类参照：`dx2020z/ad-redline-guardian` 的 `references/banned-words.md`；
- 获取通道：raw 直连不稳时走 `api.github.com`（base64）或 ghproxy 镜像；**逐文件重试＋校验**（魔数/大小/行数）；来源仓库许可核验并登记台账。
- **两边均为公开整理，非官方**——所有条目必须标注来源与"非官方整理，法条原文为准"。

**整理机制（逐条）**：

1. 采集来源词 → 去噪/去重（同词同类别唯一；跨类别同词保留＝同词异类）；
2. 挂锚点：`literal`（词面逐字见于条款，如 §9 列举词）或 `variant`（"等用语"开放列举下的变体，必须写 `note` 说明语义类属判定依据）；
3. 风险分级：`high`（明文列举/平台明确禁止的典型用语）｜`medium`（常见变体、语境依赖）｜`low`（边缘词、谨慎使用）；**分级为整理口径而非法律认定**，随条目记录理由（note 或分级说明）；
4. 写 `suggestion`（确定性替换建议，非空）；
5. `status`：完成上述核对 → `verified`；否则**不进规则包**（留 `data/wordlist-candidates.md` 工作台账：采/拒记录＋理由）。
6. **落库纪律（D-3）**：规则包文件只收挂锚点条目的 `verified` 条目；引擎门控二次兜底（K5）。

**产出**：`references/wordlists/{absolute-terms,medical,health-food,industry}.json` ＋ 校验器 `tools/validate_rulepack.py` 全过 ＋ `references/MANIFEST.json`（sha256/计数/版本派生）＋ 采拒记录。

**校验器断言**（`--check` 退出码 0/1/2）：schema/枚举；文件↔类别映射；同文件同词唯一；锚点解析（文件存在→条款可抽取→literal 词面包含）；`suggestion` 非空；排序（word 码点序）；计数与 manifest 一致。

## 4. 平台规则摘录（M1 执行卡）

**平台**：淘宝 / 抖音 / 小红书 / 视频号。

**获取策略**：官方社区规范页纯 JS 渲染（⬜ 不可自动抓）——M1 逐个尝试可达通道：官方帮助中心 / 开放平台文档 / 站内静态子页 / 官方公告页；**记录每条通道的实测结果**。仍不可得 → 如实标 ⬜＋已查渠道，降级继续（不阻塞其余模块）。

**摘录件格式**（`references/platforms/<平台>.md`）：

- 头部元数据块：平台 / 摘录日期 / 原页 URL / 摘录人 / 摘录范围（哪类违禁词）/ **性质声明**："人工摘录快照，非官方实时口径，以平台现行规范为准"；
- 正文：要点化条目（短句摘录，不全文拷贝）；
- 纪律：不得冒充官方口径；后续平台规则更新走"新增摘录件＋注明新日期"，旧件不篡改。

## 5. 合成样例与真值（M4 计划）

**纪律（沿 `data/README.md` §3，全部保留）**：

1. 假品牌名/假商品白名单（如"测试品牌A""示例商品B"），统一登记；禁止引用真实品牌案例；
2. 不植入真实内容（真实文案/案例/处罚公告一律不进样例）；
3. 真值显式登记：每条样例登记 `expect_hits`（应命中词＋位置）与 `expect_verdict`（应判为何，或 null）；
4. 每形态 ≥1 采样件＋manifest 双数（总数/采样数）登记；
5. 覆盖三类边界：语境豁免样例、同词异类样例、未命中（负样例）；
6. 覆盖度口径按规则域与异常类型列最低项（写进 manifest）；**不写会随实现漂移的硬数字**。

**结构**：`data/samples/cases.json`（冻结）＋ `manifest.json`（计数/采样清单/验收门槛），由 `tools/gen_cases.py` 确定性生成（枚举式、无随机、无时间戳、`--check` 位级一致）；真值只存"输入与期望"（禁 `observed` 类字段）。

**覆盖矩阵（生成器自动保证＋人工样例增补）**：

| 形态 | 保证方式 | 数量口径 |
|---|---|---|
| 单词命中（逐词） | 对每个 `verified` 词条枚举生成 | 采样数 = 词条总数（自动全量） |
| 多词同句 | 人工设计 | 每类别 ≥1 |
| 负样例（零命中） | 人工设计（纯良性文本） | 每类别 ≥1＋全局 ≥1 |
| 位置边界 | 行首/行尾/跨行（多行）/CRLF/BOM | 逐边界 ≥1 |
| 同词异类 | 存在跨类别同词时生成 | 逐词 ≥1 |
| 判定类（`expect_verdict`） | 人工设计（豁免/存疑语境） | ≥3，覆盖三态 |

## 6. 台账与数值口径

- **`data/README.md`** = 来源台账：查证三态（✅/⬜/不可获取）＋ URL ＋ 基准日；M1 执行后逐项回填实测（HTTP 状态、字节数、sha256 登记位置、采拒计数）。
- **一处定义**：词条/法条/平台规则只在 `references/` 定义一次；`data/README`、plan 文档、README 全部引用不复制。
- **计数纪律**：任何"词条数/样例数/测试数"必须**当轮实测**（命令输出），跨文档同步；对会随动作增长的量（如测试计数）写"取值方式＋快照点"而非裸数字。
- **版本**：规则包版本由 `references/MANIFEST.json` 内容派生（K14）。

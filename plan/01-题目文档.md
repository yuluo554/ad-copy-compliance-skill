## 1. 介绍

### 1.1 痛点

写推广文案的人（电商运营、内容创作者、代运营、个体商家）每天都在和一个看不见的雷区打交道，痛点集中在三条：

- **① 法条口径记不住**：《中华人民共和国广告法》**第九条**明确禁止使用"国家级""最高级""最佳"等绝对化用语（**"国家级""最高级""最佳"三词已实测出现在 samr.gov.cn 全文正文中**，见 §5 锚点表）。普通人既背不下法条列举项，也判不准"全网最低""销量第一""顶级"这类变体到底算不算越界。
- **② 平台规则各不相同**：抖音、小红书、视频号、淘宝各自的违禁词口径与社区规范**并不一致**——同一句文案在 A 平台能过、在 B 平台被判违规，靠人工逐平台对照社区规范页成本极高，且平台规范页多为**纯 JS 渲染**（⬜ 见 §5），机器无法自动抓取。
- **③ LLM 聊天不可复现**：直接问通用大模型"这句话违规吗"，得到的是**没有命中位置、没有依据条款、下一次可能漂移**的自然语言判断——同一个模型、同一句文案，换个问法结论就可能翻转；批量几十条文案时更是完全无法自动化、无法进 CI。

真实场景是"写完文案先自查"：一条商品标题、一段直播话术，需要在**发出去之前**被逐句扫过一遍，命中处标红、给出替换建议、附上依据条款。这件事目前只能靠人肉，或者靠不可复现的 AI 闲聊。

### 1.3 差异化打法（必写进题面，本题凭什么赢）

**不做第 6 个"又一个词表扫描器"**，做四件事的组合——即 `open-seo-mcp-skills`（5624★）式的 **"skill + MCP"组合**，该组合在广告合规领域**尚未出现**：

1. **三层规则包**：法条原文冻结（`references/statutes/`）+ 平台规则分平台（`references/platforms/`）+ 分类词表（`references/wordlists/`）——规则与代码分离，可版本化、可审计；
2. **确定性扫描器与 LLM 语境判定分工**：扫描层用 DFA/正则词表给出**可复现的命中位置**，判定层用 LLM 做**语境豁免与品类识别**（"全国销量第一"是否属于可豁免的客观事实陈述），明确"**扫描归扫描、判定归判定**"，不靠模型拍脑袋给命中；
3. **可选 MCP 查询层**：把词表/法条做成 MCP server，供其他 agent 查询（扩展项）；
4. **多平台一键适配**：同一份文案按淘宝/抖音/小红书/视频号分别输出结论（扩展项）。

## 2. 任务要求

> 首期范围限定为 **5 个模块**：SKILL.md 主入口、三层规则包、确定性扫描器、LLM 分层判定协议、真值基准；可选 MCP server、多平台适配、批量 CI 模式留扩展。全部模块遵循统一确定性纪律：**未挂原文核对不得落库/生效**；**扫描命中位置可复现**（同一输入同一命中集合，无随机性）。

### 模块 ①：SKILL.md 主入口与安装说明

- **输入**：用户在 Claude Code / Codex 中粘贴的推广文案（或指向文本文件的路径）。
- **输出**：`SKILL.md`（skill 触发描述、调用方式、输出契约、免责声明）+ `README.md` 安装说明（如何放入 skills 目录 / 如何被 agent 调用）。
- **确定性纪律**：SKILL.md 中声明的输出契约（JSON 字段）必须与 `scripts/check.py` 的实际输出**逐字段一致**，不得写"只存在于文档"的字段。

### 模块 ②：三层规则包（法条冻结 + 平台规则 + 分类词表）

- **输入**：已核对的法条原文（samr.gov.cn 直连）、人工摘录的平台社区规范、公开整理的极限词表。
- **输出**：三层 `references/` 规则素材：
  - `references/statutes/`——法条原文冻结文本（《广告法》§9 绝对化用语、§16 医疗、§18 保健食品、§28 虚假广告；《互联网广告管理办法》；《医疗广告管理办法》§6/§7 禁止性），每条带**来源 URL + 基准日 + 查证状态**；
  - `references/platforms/`——分平台规则（淘宝/抖音/小红书/视频号），**人工摘录冻结**（平台官方规范页纯 JS ⬜ 不可自动抓，见 §5），逐条注"摘录日期 + 摘录人 + 原页链接"；
  - `references/wordlists/`——分类词表（绝对化用语/医疗违禁/保健食品违禁/行业违禁），每条带**类别 + 风险等级 + 依据条款锚点**，并显式标注"**非官方整理，法条原文为准**"。
- **确定性纪律**：**未挂原文核对的词条不得落库**；法条文本为**冻结字节件**（登记 sha256），平台摘录件必须注摘录日期与出处；词表来源若为公开整理（非官方），必须标注来源与"非官方"性质，不得冒充官方口径。

### 模块 ③：确定性扫描器 `scripts/check.py`（确定性内核，亮点）

- **输入**：文案纯文本（多行，逐句）。
- **输出**：命中集合 JSON，每条形如 `[{word, category, risk, line, col, context, suggestion}]`（**仿 dx2020z/ad-redline-guardian 范式**，字段名固定）：
  - `word`：命中的词表项；
  - `category`：所属类别（绝对化用语/医疗/保健食品/行业）；
  - `risk`：风险等级；
  - `line` / `col`：命中位置（**行号 + 列号**，可在原文中逐字定位）；
  - `context`：命中处上下文窗口；
  - `suggestion`：可替换的合规改写建议。
- **确定性纪律**：用 **DFA / 正则**做匹配（多模式串一趟扫描），**同一输入 → 同一命中集合与同一位置**，无 LLM、无随机性；命中位置必须能在原文定位到逐字子串，不得静默吞掉；`suggestion` 只做**词表内置映射**（确定性替换建议），不做自由生成。

### 模块 ④：LLM 分层判定协议（语境豁免/品类识别，明确"扫描归扫描、判定归判定"）

- **输入**：模块③的确定性命中集合 + 原始文案。
- **输出**：对每条命中的**分层判定**——`confirmed`（确属违规）/ `exempt`（语境豁免，如客观事实陈述、引述他人、法定用语）/ `uncertain`（需人工复核），附**判定理由 + 依据条款锚点**。
- **确定性纪律**：**扫描层不调用 LLM**（命中位置由词表决定，保证可复现）；**判定层才调用 LLM**，且只对**已命中的候选**做语境判断，不得新增/删除命中项的位置（判定只改 `verdict` 字段，不改 `word`/`line`/`col`）；LLM 不可用时**降级为纯扫描输出**（所有命中标 `uncertain`），保证离线可用。

### 模块 ⑤：真值基准（内置评测，可复现）

- **输入**：程序化构造的**带植入真值**的合规/违规文案样例集。
- **输出**：样例集 + 真值文件（每条样例登记"应命中哪些词、应判为何"），一条命令复现评测，断言**命中集合精确匹配**（词 + 位置）。
- **确定性纪律**：基准**零外部依赖、零 API 可离线复现**；样例使用**假品牌名/假商品白名单**（不引用任何真实品牌违规案例）；真值覆盖度口径按**规则域与异常类型**列最低覆盖项（如"绝对化用语/医疗/保健食品/行业各至少 X 例"写进 manifest 或 plan/00 台账口径），**不写会随实现漂移的硬数字**。

### 扩展项（不承诺首期交付）

- **可选 MCP server**：把词表/法条做成 MCP 查询层，供其他 agent 调用（"skill + MCP"组合的第二半）；
- **多平台一键适配**：同一份文案按淘宝/抖音/小红书/视频号分别输出结论；
- **批量 CI 模式**：对文案目录/文件批量扫描，输出机器可读报告供 CI 门禁调用。

## 6. 边界与非目标

- **不做法律意见（免责红线）**：本工具是**辅助自查**，**不构成法律意见、不构成合规保证、不构成行政认定**；正式结论以主管部门口径与专业律师意见为准。SKILL.md 与输出中**强制携带免责声明**。
- **不做自动发布/自动改文案上线**：只输出体检结论与**可替换建议**（建议供人决策），**不自动改写并发布**，不对接任何平台发布接口。
- **隐私红线**：**纯本地处理、零上传**——粘贴的文案不联网上传（MCP 层亦为本地）；判定层如调用 LLM 须显式声明并可关闭（关闭后降级为纯扫描），不得默认把用户文案发往外部服务。
- **品牌隔离**：不复制姊妹项目代码；公开文档不提其余项目业务领域；**不引用任何真实品牌违规案例**，基准与演示一律使用假品牌名/假商品白名单。
- **首期范围限定**：仅"文案自查"五模块；MCP/多平台/批量 CI 为扩展项。
- **词表性质声明**：`references/wordlists/` 中的公开整理词表**非官方**，必须标注来源与"**非官方整理，法条原文为准**"；平台规则为**人工摘录**，须注摘录日期与出处，不得冒充官方实时口径。
